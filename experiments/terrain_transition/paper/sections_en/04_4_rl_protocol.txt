After the analytic evaluation, the three methods (smoothstep, calibrated Gaussian, hybrid) were compared in a real Isaac Lab/Isaac Sim training environment. This forms the centre of the study's novelty: the comparison was carried out not as an abstract numerical experiment but with a SAC training loop running inside a GPU-parallel PhysX physics simulation, on real cratered/sloped lunar terrain.

Each method, selected via the ISAACLAB_TERRAIN_BLEND_METHOD environment variable, was trained on the same hardware (single machine, single GPU), with the same SAC configuration defined in Section 3.5 (sb3_sac_cfg.yaml), and sequentially rather than concurrently, to avoid GPU/VRAM contention. Each run lasted 5,734,400 environment steps (roughly 350 iterations); this is a shortened but still meaningful-signal version of the full-scale (1200-iteration) configuration, reduced because of a compute-budget constraint, and this is a scale limitation that must be stated explicitly.

The initial measurement was made as a single run per method, with the default seed in the SAC agent's configuration file (seed = 42). Considering that this single-run design is exactly the kind of pitfall Henderson et al. (2018) warn about, the study was extended with two additional independent seeds (seed = 7 and seed = 123), yielding a total of three independent runs (n = 3) per method -- the ISAACLAB_SEED environment variable was added to the production code for this purpose. Because of the inherent nondeterminism of GPU-parallel PhysX physics simulation (thread scheduling, floating-point reduction order) and the timing dependence of the terrain pool's background CPU generation process, even two runs with the same seed are not bit-equivalent repeats of each other; the three seeds therefore sample this system-level nondeterminism in addition to the variance due to agent initialization.

Training metrics (success rate, timeout rate, harsh-landing rate, curriculum difficulty, entropy coefficient, xy-progress reward) were logged via TensorBoard, and the event files were parsed with tensorboard.backend.event_processing.EventAccumulator. For each (method, seed) run, the final performance was reduced to a SINGLE summary value by averaging the logged points in that run's final ten-percent window; comparisons among methods were made on these three independent summary values (as an independent sample) with the Mann-Whitney U test and a 5000-replicate bootstrap 95% confidence interval. This is the statistically correct unit, avoiding the use of autocorrelated (non-independent) points within a single run as a pseudo-independent sample (pseudoreplication); however, statistical power with n = 3 is low, and this point is emphasized explicitly in Section 4.3 and Section 5.
