The fine-detail height of the local patch is added to the global surface with one of three candidate fade functions. In all three functions, with r the distance from the centre and R = terrain_detail_radius_m = 8.0 m the fixed transition radius, the value is forced exactly to zero for r >= R (hard truncation); this is the key methodological arrangement that makes the three methods comparable under the same transition budget, and it is applied this way in the production code as well.

Smoothstep (compact support, default/current method): with t = clamp(1 - r/R, 0, 1), fade(r) = t^2 * (3 - 2t). This function is already exactly zero at r = R; it needs no additional truncation step, and C1 continuity is analytically guaranteed.

Gaussian (infinite support, previously used method): fade(r) = exp(-k * (r/R)^2). Two values of k are evaluated separately in this study: the previously used (as-shipped) constant k = 1.0, and the calibrated constant proposed in this study, k = ln(1000) ~ 6.9078, which brings the Gaussian's practical support down to roughly one part in a thousand at R. The cfg.terrain_gaussian_k field in the production code uses the calibrated constant by default; the as-shipped k = 1.0 was tested only in this study's analytic/CPU comparison, as a separate variant (gaussian_shipped), to demonstrate the existing defect. For both k values, the function is forced to zero externally at r >= R.

Hybrid (proposed method): with the landing-gear contact-footprint radius rc = terrain_hybrid_contact_radius_m = 1.5 m and the switch width w = terrain_hybrid_switch_width_m = 0.3 m, a smoothstep-weighted switch(r) is defined over the interval [rc - w/2, rc + w/2]: u = clamp((hi - r) / (hi - lo), 0, 1), switch(r) = u^2 * (3 - 2u), where lo = rc - w/2 and hi = rc + w/2. The final fade is defined as fade(r) = switch(r) * gauss(r) + (1 - switch(r)) * smoothstep(r); that is, the region near the foot contact zone is weighted mostly toward the Gaussian, beyond it mostly toward smoothstep, and the transition between the two functions is smoothed by a smoothstep weight that is itself C1-smooth. Since switch(r) = 0 at the r = R boundary, the hybrid method is analytically identical to smoothstep at that boundary.

These three methods are integrated into the production code, selectable via the ISAACLAB_TERRAIN_BLEND_METHOD environment variable (smoothstep | gaussian | hybrid), without changing the existing default behaviour (smoothstep).
